# Asset pipeline

These scripts and prompts produced the 3D assets in `public/`: the characters in `public/models/` and the office set in `public/assets/office/`. Generated models (GLB files), raw downloads and the source photos are not in this folder. The finished GLBs are in `public/`.

All assets were generated on Comfy Cloud. Gemini Nano Banana 2.1 made a clean reference image, Meshy 7.1 turned it into a textured model (and rigged the characters), and the Python scripts here fitted the results to the engine's conventions.

## Engine conventions

- Units are meters, Y is up, and the origin is at the bottom center.
- Props face +Z. Characters are rigged Meshy humanoids facing +Z.
- Textures are resized to at most 1024 px and stored as WebP (`EXT_texture_webp`).
- GLBs are exported with normals (`include_normals=True`).
- Every GLB is checked with the Khronos glTF validator and must have 0 errors.

## Setup

```bash
python -m venv .venv && .venv/bin/pip install -r tools/assets/requirements.txt
(cd tools/assets/node && npm install)
GT=tools/assets/node/node_modules/.bin/gltf-transform
```

## Characters (`characters/`)

| File | What it does |
|---|---|
| `workflows/<name>_tpose_reference.json` | Comfy workflow: photo(s) of the person → full-body T-pose reference (Gemini, 2K). Matt's and Steven's runs also pass Deep's finished reference as the style and pose image so the cast matches. |
| `workflows/<name>_rig.json` | Comfy workflow: T-pose reference → Meshy model (30k triangles, `pose_mode: T-pose`) → Meshy rig. It saves the rigged GLB and FBX plus an unrigged GLB. |
| `emotes.py` | Bakes the celebration clips (`point_fist_pump`, `point_flex`, `win_victory_jump`, `win_floss`) onto a Meshy rig as glTF animations. |
| `animate_preview.py` | GLB parser, skinning and moderngl renderer that `emotes.py` reuses. It also renders turntable or preview frames. |

`LoadImage` inputs show as `<upload: …>` placeholders. Upload your own image and put its returned name there.

```bash
.venv/bin/python tools/assets/characters/emotes.py bake   steven_rigged.glb steven_emotes_raw.glb
.venv/bin/python tools/assets/characters/emotes.py render steven_emotes_raw.glb frames/ win_floss   # preview; needs the un-WebP'd file
$GT resize steven_emotes_raw.glb tmp.glb --width 1024 --height 1024 && $GT webp tmp.glb public/models/steven.glb
node tools/assets/node/validate.mjs public/models/steven.glb
```

## Office (`office/`)

| File | What it does |
|---|---|
| `build_room.py <out_dir>` | Procedural game-room shell (15 × 13 m, ceiling 3.2 m): floor, walls, doors, ducts and LED strips. It also builds `exit_sign.glb`, `wall_posters.glb` and `fire_extinguisher_sign.glb`. |
| `build_net.py <out.glb>` | Procedural ping-pong net. |
| `fit_prop.py in.glb out.glb --size X Y Z [--rotate-y DEG]` | Scales a Meshy prop to real-world extents in meters (0 = keep proportional), drops it to the floor and centers it. |
| `render_props.py out.png a.glb [b.glb …] --eye … --target …` | Headless preview render, used to check that each prop faces +Z and is the right size. |
| `layout.py` | The original game-room layout (waves 1–2). **It writes `office/out/office_layout.json`, not the live file.** See below. |
| `wave2/props.json`, `wave3/props.json` | Prop name → [prompt description, target size in meters]. |
| `wave2/reference_image_items.json`, `wave2/mesh_items.json` | Wave 2 batch: Gemini reference images first, then Meshy from the uploaded references. |
| `wave3/generate_items.json` | Wave 3 batch: Gemini and Meshy chained in a single workflow per prop. |
| `wave3/entries.json` | Wave 3 placements, as sent to the engine. |

Steps for each prop:

```bash
.venv/bin/python tools/assets/office/fit_prop.py raw/coffee_bar.glb fit/coffee_bar.glb --size 1.8 1.0 0.6
$GT resize fit/coffee_bar.glb tmp.glb --width 1024 --height 1024 && $GT webp tmp.glb public/assets/office/coffee_bar.glb
node tools/assets/node/validate.mjs public/assets/office/coffee_bar.glb
```

### Who owns the layout

`public/assets/office/office_layout.json` is generated by **`scripts/layout-floor.mjs`**. That script holds the game-room entries (zone `"game"`) as well as the office floor (desks, Lora Lounge, meeting rooms, kitchen). Don't overwrite the live file with `layout.py` output: that would delete the floor. To add a prop, place it in `scripts/layout-floor.mjs`. If it should block the walker, also add its name to the `SOLID` regex in `src/world/Explore.js`.
